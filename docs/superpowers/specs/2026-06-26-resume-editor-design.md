﻿﻿﻿﻿﻿﻿﻿﻿﻿# 简历模块化编辑工具设计文档

## 1. 目标

构建一个本地网页工具，用于编辑固定模板的中文简历。

核心体验：

- 左侧为结构化编辑区
- 左侧支持大板块拖拽排序
- 右侧为实时简历预览区
- 支持导出 PDF
- 第一版只做单一模板，样式尽量贴近参考简历图

## 2. 第一版范围

### 包含

- 固定单一模板
- 本地网页运行
- 左侧结构化表单编辑
- 右侧实时预览
- 大板块拖拽排序
- 经历类条目支持新增、删除、上下排序
- 空模块自动隐藏
- 支持浏览器打印导出 PDF

### 不包含

- 多模板切换
- 小板块或字段级拖拽
- 富文本编辑
- 账号登录
- 云端保存
- 后端服务生成 PDF

## 3. 页面结构

页面采用左右双栏布局。

### 左侧

左侧分为两部分：

1. 栏目顺序区
2. 栏目内容区

栏目顺序区用于拖拽一级栏目顺序，不编辑具体字段内容。

栏目内容区用于填写各模块数据。

### 右侧

右侧为简历预览区，始终按照当前数据与栏目顺序实时渲染。

预览区不直接编辑，只负责展示与导出。

## 4. 模块顺序

默认展示顺序如下：

1. 基本信息
2. 核心优势
3. 项目经历
4. 工作经历
5. 教育经历
6. 相关技能
7. 其他信息

规则如下：

- 基本信息固定在最上方
- 其余大板块支持拖拽排序
- 小板块和字段布局固定，不参与拖拽

## 5. 数据结构设计

页面维护两类核心状态：

### 5.1 简历内容

使用 `resumeData` 对象存储表单内容：

```ts
type ResumeData = {
  basicInfo: {
    name: string;
    phone: string;
    email: string;
    wechat: string;
  };
  coreStrengths: string[];
  projects: ProjectItem[];
  workExperiences: WorkItem[];
  educations: EducationItem[];
  skills: {
    languages: string[];
    tools: string[];
    interests: string[];
  };
  others: string[];
};
```

### 5.2 大板块顺序

使用 `sectionOrder` 数组存储可拖拽大板块顺序：

```ts
type SectionKey =
  | "coreStrengths"
  | "projects"
  | "workExperiences"
  | "educations"
  | "skills"
  | "others";
```

说明：

- `basicInfo` 不进入 `sectionOrder`
- 右侧预览通过 `sectionOrder` 决定各大板块渲染顺序

## 6. 各模块字段设计

### 6.1 基本信息

字段如下：

- 姓名
- 电话
- 邮箱
- 微信

展示规则：

- 姓名置顶居中或显著展示
- 联系方式展示为同一行或相邻两行

### 6.2 核心优势

字段如下：

- 优势要点列表，支持多条

展示规则：

- 展示为一句或多句摘要内容
- 优先保持简洁，避免占用过多版面

### 6.3 项目经历

每条项目包含：

- 项目名称
- 项目角色
- 项目时间
- 项目简介
- 项目成果列表
- 使用工具或技能（可选）

展示规则：

- 首行展示项目名称与项目角色
- 次行展示项目时间
- 简介单独成段
- 成果使用项目符号分条展示
- 工具或技能存在时补充在简介后或成果前

### 6.4 工作经历

每条工作包含：

- 公司名称
- 岗位名称
- 工作地点
- 任职时间
- 工作内容列表

展示规则：

- 首行展示公司名称
- 次行展示岗位名称、工作地点与任职时间
- 工作内容使用项目符号分条展示

### 6.5 教育经历

每条教育包含：

- 学校名称
- 专业
- 学历
- 在校时间
- 补充说明（可选）

展示规则：

- 首行展示学校名称
- 次行展示专业、学历与时间
- 补充说明存在时以简短要点展示

### 6.6 相关技能

字段如下：

- 语言列表
- 工具或技能列表
- 兴趣爱好列表

展示规则：

- 优先简洁展示
- 使用短句或分隔形式展示

### 6.7 其他信息

字段如下：

- 其他补充信息列表

展示规则：

- 仅在存在内容时显示
- 保持紧凑，避免冗余空白

## 7. 编辑交互设计

### 7.1 左侧结构化表单

左侧编辑区按模块展示表单。

规则如下：

- 每个模块独立成组
- 经历类模块支持新增条目
- 经历类模块支持删除条目
- 经历类模块支持上下排序
- 字段顺序固定，不做字段拖拽

### 7.2 大板块拖拽

单独提供栏目顺序区，用于拖拽一级栏目。

规则如下：

- 仅支持大板块拖拽
- 基本信息固定，不参与拖拽
- 拖拽后立即更新右侧预览顺序
- 拖拽只影响展示顺序，不修改模块内部字段结构

### 7.3 空模块处理

规则如下：

- 某个模块无内容时，右侧预览自动隐藏该模块
- 模块隐藏不删除用户数据
- 用户重新填写内容后可恢复显示

## 8. 预览设计

右侧预览区使用固定简历模板。

要求如下：

- 样式尽量贴近参考简历图
- 结构清晰，强调标题、时间、组织名称和要点
- 长文本自动换行
- 不出现字段空白占位
- 优先保障打印和 PDF 导出稳定

## 9. PDF 导出方案

第一版采用浏览器打印样式导出 PDF。

流程如下：

1. 用户点击导出 PDF
2. 页面切换到打印样式
3. 隐藏左侧编辑区和操作区域
4. 保留右侧简历内容作为打印主体
5. 调起浏览器打印，并由用户选择另存为 PDF

选择该方案的原因：

- 开发速度快
- 不依赖后端
- 右侧预览和导出内容一致
- 更适合第一版快速交付

## 10. 组件划分

建议组件如下：

- `ResumeEditorPage`
- `SectionSorter`
- `BasicInfoForm`
- `CoreStrengthsForm`
- `ProjectExperienceForm`
- `WorkExperienceForm`
- `EducationForm`
- `SkillsForm`
- `OtherInfoForm`
- `ResumePreview`
- `ExportActions`

## 11. 数据流

整体采用单页前端状态驱动。

数据流如下：

- 左侧表单修改后更新 `resumeData`
- 大板块拖拽后更新 `sectionOrder`
- 右侧 `ResumePreview` 根据 `resumeData` 和 `sectionOrder` 实时渲染
- 导出 PDF 直接复用预览 DOM 与打印样式

该方案将内容编辑和版块排序分离，便于后续扩展多模板或更复杂编辑能力。

## 12. 异常与边界处理

需要处理以下情况：

- 某条经历缺少可选字段时自动收口，不显示空行
- 要点内容过长时自动换行
- 模块内容为空时自动隐藏模块标题
- 多条经历较多时仍保持可读排版
- 时间格式统一为 `YYYY.MM-YYYY.MM`

## 13. 测试重点

- 左侧输入与右侧实时同步
- 大板块拖拽排序正确
- 项目经历、工作经历、教育经历的新增、删除、排序正常
- 空字段和长文本下版式稳定
- 打印预览与导出 PDF 版式一致

## 14. 技术建议

第一版建议采用纯前端单页实现。

建议原则：

- 优先使用轻量状态管理
- 先保证模板、交互和导出稳定
- 后续再扩展多模板与更细粒度模块化能力

## 15. 后续扩展方向

后续可扩展能力包括：

- 多模板切换
- 模板样式配置
- 更丰富的字段类型
- 大板块显隐配置
- 小板块拖拽
- 云端保存
- 导入和导出 JSON
